# 스크립트 구조에 대한 해석
- A -> B -> C를 상속받는 구조라고 생각해보자. 당연히 뉴비는 C에 대한 작업이 들어올 것 이다. 그리고 당연히 C에 대한 리딩만 진행했고 A,B는 대충했다. 하지만 근본적으로 A,B를 잘읽어야 C의 작업이 쉬워지고 중복이 없게 된다.
  - A에 가상함수로 들어온 것도 결국에는 C에서 오버라이딩 하라는 의도.

# 오버라이딩
- ![image](https://user-images.githubusercontent.com/55792986/213597329-7b59bc93-3109-452f-9843-c27807f3a597.png)
  - C : B : A 구조의 상속에서 A에 virtual로 만들고 B 건너뛰고 C에 오버라이딩이 되긴 한다.
  - 이럴 때 C에서 base를 이용하면 A꺼를 가져온다. C에도 있고 B에도 있고 A에도 있으면 C에서 base를 했을 때 B를 가져온다.
- 너무 당연하지만... C에서 구현하지 않고 B에 있는 메서드를 호출하는 게 당연히 된다.

# this
- 매개변수에 this가 있으면 이는 생략되서 넘겨도 된다.
  - 다시말해 매개 변수가 2개인데 한 개가 this가 붙은 매개변수라면 인자로 1개만 넘겨주면 된다.
  - 메서드 앞에 객체가 this가 된다.
