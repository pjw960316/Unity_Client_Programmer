# 의존성을 이해한 것
- A 클래스에서 어떤 데이터를 가져온다고 가정해보자.
  - 데이터 관련 클래스에도 해당 데이터가 있고 그 데이터를 출력시켜주는 UI에도 해당 데이터는 표시되고 있다.
- 결론부터 말하면 데이터 클래스만을 참조해서 A 클래스에서 데이터를 사용해야 한다.
- 하지만 나는 해당 데이터를 표시해 주는 UI를 참조해서 A 클래스에서 해당 데이터를 참조했다.
  - 이는 '의존성'에 큰 문제를 나타낸다.
  - 만약 그 UI가 없어진다면 A 클래스는 문제가 발생한다. (참조할 게 없어지니까.)
- 이는 개발자의 구현 설계에서 매우 중요하다.
- 데이터는 데이터 클래스에서만 가져오자. 

# 데이터 파일도 이해해라
- 당연히 코드만 이해해야 한다고 생각했다.
- 하지만 개발자는 데이터가 저장된 파일 (excel, xml)의 구조도 이해해야 한다.
  - xml이라면 해당 xml에 저장된 데이터가 어떤 구조로 구현되어 있으며 (key, value)가 어떤지도 명확히 이해해야 한다.

# 개발자의 개발 순서
- 구현해야 할 내용과 관련된 스크립트를 전부 코드 분석(흐름 파악)하고 구현을 해라.
  - **:star:흐름 파악과 해당 클래스의 구조와 중요 메서드의 동작을 모르면 재사용 할 수 있는 클래스와 메서드를 사용하지 않고 생으로 다시 짜는 불상사가 발생한다.**
