# 개요
- 가장 중요한 챕터

# 팁
- 불 필요한 열 참조 하지 않는다.
  - SELECT *을 지양한다.

# 용어
- SARG = Search Argument = 검색 인수
- Non-SARG = Non-Search Argument = 비 검색 인수
- where절과 join의 on절에는 조건식이 오며 이를 predicate라고 부릅니다.
  - :star:다 검색하지 말도록 predicate를 적는 규칙이 있다. 이게 SARG다.
  - optimizer가 최적화를 하는 과정에서 방해가 있으면 안 된다.

# :star: :star: :star:오늘 강의에서 가장 중요한 내용 : 쿼리의 금기 사항 : NON-SARG
- 부정형을 사용하지 않는다.
  - 부정형을 쓰면 optimizer가 긍정형으로 바꿔 버린다.
  - 조건은 '='이 가장 빠르고 효율적이다.
- NOT IN은 가급적이면 사용하지 않는다.
  - 최후의 보루.
- 불필요한 값을 변형하지 않는다.
  - Index 열에 사칙 연산을 적용하지 않는다.
    - 근데 SQL을 잘 모르니까 이 부분을 들어도 이해가 가지 않는다.
- 형 변환 규칙은 DBMS 마다 다르다. 
- 열 간 비교되지 않도록 다른 형식으로 구현한다.

# index

- 첫 문자는 반드시 상수 문자여야 한다.
- like는 반드시 문자형에만 사용해야 한다.
- 마찬가지로 인덱스를 적을 때는 있으나 마나한 쿼리를 제외시킨다.

# 조건절 상수화 이슈
- @를 이용한 로컬 변수
  - 이건 런타임 때 값이 할당되므로 컴파일 때는 Unknown 상태
- Optimizer는 컴파일 타임에 변수의 값이 뭔지를 알아야 최적화(=튜닝)를 할 수 있다.

# In vs Between
- In
  - 검색 대상이 아주 적은 경우에 적합하다.
  - Equal 조건이 필요한 경우.
- BETween
  - Non-Equal 조건과 AND 연산 결합.
  - 연속 값 검색에 유리하다.
