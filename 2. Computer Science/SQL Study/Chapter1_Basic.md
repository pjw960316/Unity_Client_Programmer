# 쿼리 성능 측정
- 실제 실행 계획 포함이라는 기능을 켜고 쿼리를 실행시키면 된다.
- I/O : 논리적 읽기의 숫자를 파악하면 커리에서 읽은 page(8KB)의 수.

# 개발 및 관리 도구시 주의
- 클라 개발자는 DB 전문가가 아니므로 직접 DB에 접근하지 않는다.
- 여러가지 개발 도구를 이용해서 DB에 접근하면 부하가 크다.
  - select *을 써서 DB 전체를 읽어버리는 부하가 생길 수 있다.
    - 바로 서비스 장애 발생.

# 제목 모름
- 순서가 상관이 없어서 성능이 동일한 것
  - optimizer가 알아서 최적화 한다.
  - select
  - where
  - join
- optimizer가 outer join은 최적화를 하지 못 하므로 불 필요한 outer join은 하지 않는다.

# varchar vs char
- varchar
  - 가변 길이
- char
  - 고정 길이
- 가변길이 타입과 고정길이 타입에 대해서 공백을 처리하는 로직이 다르다.
- 가변길이와 고정길이 모두 문자열 오른쪽에 있는 공백은 알아서 무시 되므로 r_trim 할 필요가 없다.

# 의미 오류
- 불 필요한 내용을 작성한 sql 코드
  - 해당 부분을 해석하면 의미 없는 코드다.
    - 사과가 5개보다 많은지 or 사과가 3개보다 많은지
      - 5개보다 많은지는 파악할 필요가 없다.
    - 국가 그룹 목록에서 각각의 국가 이름을 선별하고 또 거기서 국가 이름을 선별하는 작업
    - 값이 1개인데 정렬시키는 행위.
- 아래는 예시 코드다.
    ~~~sql
    WHERE pk_col is NULL
    WHERE Quantity < 0
    WHERHE ShipVIA > 4 OR ShipVIA > 2
    SELECT 50 orders // orders의 별칭으로 50이 된다. 원래의 의도와 다르게 출력된다.
    ~~~
