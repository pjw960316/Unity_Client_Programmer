# 동기와의 이야기로 이해한 내용 (틀릴 수도 있음!)
- 소켓은 결국 클라와 서버가 통신하기 위해 열어 놓은 문과 같다.
- 서버의 소켓은 1개고 클라의 소켓도 1개이지만, 하나의 서버와 연결한 클라는 몇 만명이 될 수도 있다.
  - 그래서 나는 서버에 소켓(세션)을 전달해주어(클라의 정보를 전달) 해당 클라가 누구인지 파악한다고 이해했다.
- 동기는 소켓을 세션과 동등하게 생각해도 무방하다고 한다. 내가 이해한 것은 세션이 소켓을 포함하는 것 이다.
- 소켓은 네트워크 장비와 연관이 되어 있고 이를 구현하는 세션에서는 소켓의 행동을 네트워크 장비와 연관 지어 메서드로 구현한다.
  
# 세션 (Session)
- **세션은 클라이언트다.**
  - 서버 입장에서 클라이언트를 구분하기 위해 세션을 사용하고 세션 리스트에서 세션 아이디를 키로 이용해서 검색한다.
    - **세션은 소켓을 들고 있다.**
- 확실하지는 않지만 서버는 소켓과 메시지를 필요로 한다.
  - 소켓이 세션안에 저장되어 있으므로 '세션의 아이디 -> 세션 리스트에서 원하는 세션 찾기 -> 소켓'의 구조로 찾는다.
  - 메시지는 아직 정확히 어디에 있는지 모른다. 
- 쿠키는 네트워크에서 전달하는 정보를 암호화 하지 않기 때문에 보안이 약하다. 이를 보완하기 위해 세션은 암호화를 한다.
