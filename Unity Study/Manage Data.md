# 나는 이전에 어떻게 데이터를 관리했는가?
1. 당연히 처음에는 하드코딩을 했다.
2. 3학년 파일 처리 수업 : 게임의 실행과 무관하게 영구적으로 데이터는 저장되어야 한다. -> .txt 파일로 데이터를 저장
3. 3학년 데이터 베이스 수업 : SQL을 이용해서 데이터를 관리하는 방식을 배웠으나 실제로 게임에서 적용해보지는 않았다.
4. 4학년 android 프로젝트 : NoSQL인 Firebase를 이용해서 데이터를 관리했다. app 프로젝트였기 때문에 가능했다
5. 4학년 unity 프로젝트 : **json**을 이용해 데이터를 관리했다. 
- *솔직히 학창 시절에는 결국 하드코딩이었다...*
6. 회사 : **csv**와 **lua의 table**을 이용해 데이터를 관리했다. 라이브게임에서 어떻게 데이터를 관리하는지 배웠다. 서버와 데이터를 공유한다. 서버에서 검증도 하고.

# 결론
- 경험은 많지만 제대로 관리해 본 건 회사에서의 경험 뿐이다. 심지어 이건 유니티에서 해 본 것도 아니다.
- **MVC 패턴에서의 모델**을 유니티에서 어떻게 설계할지 고민해야 한다.
- 새로운 회사에서의 프레임워크에서 좋은 데이터 관리 방식을 배우고 발전시켜보고 싶다.

# 데이터 관리가 중요한 이유
- 데이터 관리를 전문적으로 하는 스크립트가 없다면 데이터를 호출하거나 가공하는 함수가 중구난방으로 사용 될 것 이다.
  - 이는 유지보수 단계에서 답이 없다.
- 데이터를 관리하는 스크립트에서 필요한 함수를 많이 제작한다.
  - 변경사항이 발생해도 해당 함수만 변경하면 된다.
- **하나의 데이터를 모두 참조**하는 방식
  - 하나의 데이터를 여러군데에서 만든다? -> 해당 데이터의 변경사항이 발생한다면 모두 찾아서 고쳐야 한다!
  
# 방식
- Json이나 Csv 파일을 데이터를 만드는 팀원이 줄 것 이다.
  - 개발자는 이를 메모리에 저장하고 관리하는 스크립트를 구현해야 한다. 
- 데이터 관리 스크립트
  - 작은 프로그램이라면 하나의 DataManager
  - 큰 프로그램이라면 데이터 마다의 스크립트. Dragon, Skill 같이 스크립트를 구분하여 데이터를 저장한다.


# 연습 : 미니언 설계 [Link](https://github.com/pjw960316/Better_Unity_Skill/blob/main/Better%20Unity%20Skill/Assets/Scripts/Minion.cs)
### 1. 개요
- *좀 더 좋은 방법이 반드시 있을 것 이지만 이는 회사의 좋은 프레임워크를 참조하며 발전 할 수 있을 것. 일단은 나의 데이터 프레임워크를 구축해본다.*
- 미니언, 몬스터, 캐릭터 데이터 3개만 필요한 롤을 구현한다고 가정하자.
  - 각각은 json 데이터로 구현되어 있다.
- 세 가지 모두 모델 데이터이다. 그러므로 각각의 스크립트를 만든다.

### 2. Minion Data Script
- 간단한 것 들은 자료구조에 저장.
- 복잡한 것 들은 클래스에 저장.
- 이들은 절대로 변경할 수 없게 해야 한다. 어떻게?
- 관리자에 저장된 데이터들은 결국 상태다. 상태는 다른 클래스에서 접근할 수 없게 해야함 -> private
  - 다른 클래스에서 데이터를 요구하면 getter, setter를 이용한다.
  - 회사의 프레임워크에는 데이터 뭉치의 특정 데이터를 읽는 함수가 잘 구현되어 있었고, 프레임워크에 없는 것들은 직접 만들었다.

### 3. json data & 자료구조
- 유니티에서 json 데이터를 저장하기 위해서는 클래스가 필요하다.
  - 하지만 해당 클래스는 struct의 느낌(데이터만 갖는)으로 이용되기 때문에 기능이 필요하면 모두 구현해야 한다.
  - 유니티의 자료구조를 사용하면 적절한 양의 기능들을 이용할 수 있다.

### 4. key를 통해 데이터를 가져오는 경우
- uid나 이름을 통해 원하는 데이터를 가져온다.
  - 이 들은 보통 parameter가 된다.
- 만약 uid나 이름이 변경되면 인자를 모두 변경해야 하는가?
- 결론적으로 하드코딩이 없을 수 있나?
