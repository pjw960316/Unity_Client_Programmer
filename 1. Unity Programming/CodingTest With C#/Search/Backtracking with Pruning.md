## :fireworks: BackTracking
- 완전탐색을 하면 시간초과가 나는 문제를 해결하는 방식이다.
- **재귀는 Depth가 조금만 증가해도 지수증가다.**
  - 엄청난 계산량을 생성한다.
  - 그러므로 prunning(=불필요한 경우를 제거)을 통해 불 필요한 분기에 진입하지 않도록한다.
- **문제의 난이도에 따라 prunning 조건의 개수가 증가한다.**
  - visit은 보통 기본적인 prunning의 조건이다.
- **조합은 DFS에서 Depth 마다 <ins>이전 원소보다 크기가 크면 중복이 없음</ins>을 이용한다.**

## 연구중...
- 제일 중요한 거!!!
  - visit 배열이든, arr 배열이든, 예를 들어 visit[1]이 무엇을 의미할까? 어떤 리스트의 1번 인덱스를 의미할 수도 있고, 그냥 값 1을 의미할 수도 있다. 이걸 제대로 설정하고 depth 마다 알맞게 상태를 저장하는 게 백트래킹의 알파이자 오메가다.
  - 깊이 마다의 상태를 계속 갱신하는 게 제일 중요하다. 그러면 상태는 곧 데이터 자료구조. 보통 depth 마다의 데이터 자료구조를 의미한다.
- 이해가 안 가면 실제로 트리를 그려라
- 백트래킹
  - 상태를 최소 범위로 만들고, 빠르게 쓰고 버리는 기술
  - 엔티티들의 상태를 재귀적으로 탐색 + 가지치기(pruning)
  - ⭐그러므로 depth마다의 상태를 저장하는데. 어려운 문제일수록 가지치기의 조건을 만들기 위해 다양한 상태가 필요하다.
- 가능한 선택지를 만들고, 조건 안 맞으면 되돌린다 → 현업 사고
- 데이터를 depth 마다 지우고 다시 갱신하고 하는 건 결국 덮어쓰기고 이는 배열에서 좋다.
