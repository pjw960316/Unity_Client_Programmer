## :fire: for(int idx=0; idx<list.Count; idx++)에서 중간에 원소 삭제할 때 index 와 count 주의점
- for문의 idx++은 최종 판별식이니, 다시 0부터 돌리고 싶으면 idx = -1이 필요하다.
- for문에 list.Count를 넣어서 매 번 갱신시키므로 값 타입 캐싱한다.

<br><br>

## :fire: 많이 반복되는 for문에서, 방향과 등호는 통일 시켜야 실수 하지 않는다.

<br><br>


## 나의 코딩테스트 기본 규칙

---

- **변수 이름은 다음과 같이 통일한다.**
    - **순회**
        - idx = 인덱스
        - i, j, k = foreach
        - pair = foreach ValueTuple
        - kv = foreach Dictionary
        - word = char
    - **container**
        - List = list  ,  HashSet = hashSet  ,  Dictionary = dict
            - dp = dp배열
            - path = 동서남북 배열
    - **순차 변수**
        - n1, n2, n3 같이 알파벳 + 숫자로 사용한다.
- **값이 0이면 종료한다는 명시적으로 ==0으로 검사한다.**
    - ≤0으로 검사하면 예외를 찾기 매우 어렵다.
- 4개 이상의 if/else를 보면 함수와 Dictionary<k,v> 구조를 생각한다.
    - 반복되는 기능은 함수로 구현한다.
    - if/else의 분기 state를 dictionary의 key로 바라본다.
        
        [코드](https://www.notion.so/31129daafd668084926af2abfcc70163?pvs=21)
        
- **변수는 캐싱을 자주하여 가독성과 안정성을 확보한다. (변수 이름은 너무 길지 않은 게 좋다.)**
    - 타입을 한 번 더 생각하기 때문에 실수를 줄일 수 있다.
    - 조건식도 bool에 저장하는 게 훨씬 가독성이 좋고 안정하다.
    - 루프 내부 지역 변수는 루프 내부에서 선언한다.
        - scope가 줄고, 스택에 잡히기 때문에 최적화에도 이슈가 없다.
- ⭐**이중 For문의 경우 내부 구조를 메서드로 분리해서 불필요한 Flag를 없앤다.**
- **for문이 순차적으로 진행되지 않으면 while을 사용한다.**
- **Int32 대신 int를 사용하고, Int64 대신 long을 사용하고, String 대신 string을 사용한다.**
    - int.MaxValue  /  int.MinValue 적극적으로 사용.
