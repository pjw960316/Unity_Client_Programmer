  - 당시의 긴 메모를 지금 사용 중인 월간 계획표 형식으로 다시 가공했습니다.
  
  - 중요한 내용은 매일 볼 수 있는 위치에 두고 반복해서 읽습니다.
  
  - 다시 볼 때마다 고치고 줄이며, 실제로 사용할 수 있는 짧은 기록으로 정제합니다.

- 그 기록을 실제 판단 기준으로 사용하고, 결과를 복기해 다시 수정하는 과정을 반복하면서 상위 랭커까지 올라갔습니다.

# 📝 Part 2 &nbsp;:&nbsp; 기록을 제 것으로 만드는 공부

### 4️⃣ Codex와 개발하며 배운 내용을 제 언어의 기록으로 남깁니다.

<div style="text-align: center;">
  <img src="./captures/3-4_study.png" width="550">

- **업무 중**
  - Codex가 AGENTS.md와 기존 GitHub 기록을 읽은 상태에서 개발하고 합니다.

  - 새로 나온 개념과 설계 기준을 공부 문서에 자동으로 추가합니다. 

  - 이 덕분에 문서를 직접 찾고 정리하는 시간이 줄어 개발 흐름을 끊지 않을 수 있습니다.

<br>

- **업무가 끝나고**
  - 업무가 끝난 뒤에는 제가 Codex가 자동으로 추가한 내용과 변경 기록만 확인합니다. 

  - 전체를 처음부터 다시 정리하지 않고 필요한 부분만 추적할 수 있어, 여기서도 복습에 드는 시간을 줄일 수 있습니다.

<br>

- **Notion과 TFT에서 배운 부분**
  - 하지만 1~3번의 자동화까지만 하면 결국 AI가 만든 기록일 뿐이라 제 공부가 되지 않았습니다. 
  
  - 가장 중요한 것은 5~6번처럼 다시 읽고 제 언어로 고쳐 판단 기준으로 만들고, <br> 그 기록을 이후의 저와 Codex가 다시 참고하는 반복 과정입니다.

<div style="page-break-after: always;"></div>


# 📝 Part 2 &nbsp;:&nbsp; 기록을 제 것으로 만드는 공부

### 5️⃣ AI 덕분에 복습과 판단에 더 집중할 수 있게 되었습니다.

- 많이 메모하는 것보다 <br> **기록을 수 없이 고치고 다시 읽고** <br> 저의 것으로 만드는 과정이 공부라는 것을 알게 되었습니다.

<br>

- 하지만 직장 생활을 하면서 이 과정을 모두 직접 하기에는 시간과 에너지가 부족했습니다. <br> 지금은 Codex가 문서를 찾고, 내용을 추가하고, Markdown 형식을 정리하는 과정을 도와줍니다. <br> 공부에 들어가는 부수적인 시간을 크게 줄여주고 있습니다.

<br>

- 덕분에 저는 Codex가 만든 초안을 다시 읽고, **제 언어로 다듬으며 복습하는 과정**에 집중하면 됩니다. <br> 이 정도의 시간은 현실적으로 꾸준히 투자할 수 있었습니다. <br> 실제로 반복하면서 계속 이어갈 수 있는 공부 방법이라는 확신이 생겼습니다.

<br><br>

> 4년 동안 혼자 쌓아온 GitHub 기록을 Codex가 읽고 제 설계 기준을 참고하기 시작했을 때, 
> 그동안 계속 기록해온 시간이 헛되지 않았다는 생각이 들었습니다.

# 🎮 Part 3 &nbsp;:&nbsp; 직접 구현에서 AI 협업까지

#### 3장 방향성

- 〈박지원 키우기〉를 개발하면서 내가 배운 핵심 세 가지를 뽑는다. 각 글을 읽고 나면 내가 어떤 상황에서 어떤 결정을 내리는지 하나씩 남아야 한다.
각 배움 안에서 변화가 보이게 쓴다. 회사에서 겪은 문제 → GPT에 질문하며 직접 구현하면서 얻은 판단 기준 → Codex와 개발하면서 그 기준을 적용한 결과. 회사 경험은 짧게 두고, 직접 구현하며 생각이 바뀐 지점에 가장 많은 분량을 쓴다.

- Codex와 작업한 경험에서는 내 판단을 구체적으로 적는다. 내가 먼저 정한 것, 맡긴 것, 결과를 보고 확인하거나 고친 것을 구분한다. 1·2장에서 이야기한 AI 활용과 공부 방식이 실제 개발에서 어떤 선택으로 이어졌는지 보여준다.

- 게임은 실제 화면과 한 문장으로 소개한다. 각 글에는 그 판단을 확인할 수 있는 코드 변경, 커밋, 실행 결과 중 하나를 붙인다. MVP나 클래스 구조는 그 선택을 이해하는 데 필요한 만큼만 설명한다.

- 월요일 첫 작업은 후보 세 개를 적는 것. 각 후보 옆에 ‘예전에는 어떻게 했나’, ‘지금은 무엇을 다르게 결정하나’, ‘그 차이가 실제 코드 어디에 남아 있나’를 한 줄씩 써본다.
