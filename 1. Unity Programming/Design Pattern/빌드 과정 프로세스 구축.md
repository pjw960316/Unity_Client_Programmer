- pc build <-> Android build 전환 자체가 생각보다 코스트가 많이 든다.
- 빌드 머신을 따로 둘 수도 없는 상황.
- 현재는 노트북은 pc build  ,  집 컴퓨터가 android build를 담당 중.
- 가장 최적화 된 방식 연구
- 빌드 머신이 없는 상태니까 이런 고민을 하는 것.

## :sparkles: Android 실기기 테스트용 빌드 프로필

#### :white_check_mark: 경험

- Android 기기를 자주 쓸 수 없어서 앱 푸시를 수정하고 바로 확인하기 어려웠다. 물 알림은 밤 9시에 예약되어 있어 기기를 쓸 수 있는 시간에 반복해서 확인하기도 어려웠다.
- 물 알림부터 테스트하되, 앞으로 다른 Android 기능에도 같은 조건을 쓸 수 있게 공통 테스트 심볼로 `ANDROID_TEST_MODE`를 정했다.

<br>

#### :white_check_mark: Scripting Define Symbols

- Scripting Define Symbols는 `#if`에서 확인할 **컴파일 심볼을 등록하는 설정**이다. 빌드 설정의 목록에 심볼 이름을 추가하면 그 빌드에서 정의된다.
- `ANDROID_TEST_MODE`가 정의되어 있으면 `true`가 되어 `#if`의 테스트 분기가 컴파일된다. 정의되어 있지 않으면 `false`가 되어 `#else`의 일반 분기가 컴파일된다.
- 여러 Android 기능에서 같은 심볼을 확인할 수 있다. `#region`은 관련 코드를 접어두는 데 쓰이고, 테스트 분기는 `#if ANDROID_TEST_MODE`로 선택한다.

<br>

#### :white_check_mark: 빌드 목적에 맞춰 프로필 만들기

- 실기기 테스트 APK는 `Android Test Build` 프로필로 만든다. 이 프로필의 `Build Data → Scripting Defines`에 `ANDROID_TEST_MODE`를 등록하면 테스트 분기가 포함된다.
- 기본 Android 프로필에서는 심볼이 정의되지 않아 일반 동작을 사용한다. 물 알림의 일반 동작은 매일 밤 9시에 예약하는 것이다.
- `LocalPushManager`에는 테스트 분기를 열어두었다. 테스트 빌드에서 물 알림을 1분 간격으로 예약하는 부분은 구현할 내용으로 남아 있다.
