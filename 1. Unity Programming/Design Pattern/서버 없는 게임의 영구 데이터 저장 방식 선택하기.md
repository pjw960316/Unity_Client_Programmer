## :sparkles: 서버 없는 게임의 영구 데이터 저장 방식 선택하기

#### :white_check_mark: 경험

- 물 섭취 기능을 만들면서 최근 몇 개월의 지급 포인트와 이번 달 보상 확인일을 앱 종료 후에도 남겨야겠다고 생각했다.
- XML, ScriptableObject, PlayerPrefs의 개념은 대강 알고 있지만, 머릿속에서 혼동되어 선택 기준이 필요하다고 느꼈다.
- JSON과 XML은 내 기준에서 비슷하게 느껴진다. 회사에서는 XML만 사용했기 때문에 우선 XML이 익숙하다.

<br>

#### :white_check_mark: 우선 구분할 종류

여기서 영구 저장은 앱을 껐다 켜도 사용자 기록을 복원할 수 있도록 데이터를 남기는 것을 뜻한다.

| 종류 | 간단한 구분 |
| --- | --- |
| JSON | 객체와 목록을 텍스트로 표현하는 형식. 파일로 저장하여 진행 상태나 보상 이력을 남길 수 있다. :airplane: [공식 문서](https://learn.microsoft.com/en-us/dotnet/standard/serialization/system-text-json/overview) |
| XML | JSON처럼 객체와 목록을 파일에 저장하는 데 사용할 수 있는 형식. 태그로 데이터를 표현한다. :airplane: [공식 문서](https://learn.microsoft.com/en-us/dotnet/standard/serialization/xml-and-soap-serialization) |
| PlayerPrefs | 정수·실수·문자열을 키와 값으로 저장하는 Unity 기능. :airplane: [공식 문서](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/PlayerPrefs.html) |
| ScriptableObject | 개발 중 설정·기본 데이터를 에셋으로 만들어 사용한다. 배포한 게임에서 변경된 사용자 기록을 자동으로 영구 저장해 주지는 않는다. :airplane: [공식 문서](https://docs.unity3d.com/6000.1/Documentation/Manual/class-ScriptableObject.html) |

<br>

#### :white_check_mark: Codex 보완 제안 — 간단한 판단 기준

- 음량·언어 설정처럼 개별 값 몇 개를 남기려면 PlayerPrefs부터 검토한다.
- 날짜별 보상 이력처럼 여러 기록을 묶어 저장하려면 JSON·XML 파일 저장부터 검토한다. 둘 중에서는 기존 저장 코드, 익숙함, 필요한 데이터 표현을 기준으로 고른다.
- 개발자가 미리 만드는 공통 설정·기본 데이터라면 ScriptableObject를 검토한다. 플레이 결과를 남기는 저장 방식과 용도를 구분한다.

<br>
