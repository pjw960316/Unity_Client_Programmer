## :fireworks: 게임 전역 설정 데이터 관리
- 게임의 여러 기능과 모든 사용자가 같은 규칙을 사용해야 하는 값은 한 곳에서 관리한다.
- 저장 방법부터 정하지 않고, 누가 값을 변경하며 어느 범위에 적용되는 데이터인지 먼저 판단한다.

<br><br>

## :fire: 게임 전역 설정 데이터의 의미
> 사용자 플레이로 변경되지 않고 개발자 또는 운영자가 결정하며, 동일한 설정 버전을 사용하는 게임 전체에 공통으로 적용되는 데이터다.

- 롤토체스의 8레벨 필요 경험치처럼 같은 패치 안에서는 모든 사용자가 같은 규칙을 사용해야 한다.
- HabitGame의 `MoneyPerRoutineSuccess`, `MoneyPerSiestaMinute`도 게임의 보상 규칙이므로 게임 전역 설정 데이터에 해당한다.
- 사용자가 루틴을 수행하거나 낮잠을 기록했다고 해서 설정값 자체가 달라지지는 않는다.
- 앱 버전이나 서버 설정 버전이 다르면 값이 달라질 수 있으므로, 모든 디바이스에서 영원히 같은 값이라는 의미는 아니다.

<br><br>

## :fire: 데이터는 변경 주체와 생명주기로 먼저 분류한다.

| 데이터 분류 | 변경 주체 | 예시 | 관리 위치 |
| --- | --- | --- | --- |
| 게임 전역 설정 데이터 | 개발자·운영자 | 보상량, 필요 경험치, 확률 | C#, ScriptableObject, 설정 파일, 서버 |
| 사용자 저장 데이터 | 사용자·게임 플레이 | 재화, 루틴 기록, 낮잠 기록 | `persistentDataPath`, 서버 |
| 런타임 임시 데이터 | 실행 중 코드 | 현재 선택, 타이머, 캐시 | 메모리 |

- 같은 XML 형식을 사용하더라도 게임 설정과 사용자 저장 데이터는 책임이 다르다.
- 하나의 값이 두 위치에 중복되면 어느 값이 기준인지 판단하기 어려워진다.
- 따라서 하나의 설정에는 하나의 기준 데이터만 둔다.

<br><br>

## :fire: 게임 전역 설정을 관리하는 방법

| 방법 | 선택하는 상황 | 특징 |
| --- | --- | --- |
| C# `public const` | 값이 적고 단순하며 개발자만 변경 | 구현이 가장 단순하고 타입이 명확하다. 변경하려면 앱을 다시 빌드해야 한다. |
| C# `static readonly` | 실행 시 계산하거나 `const`로 표현할 수 없는 값 | 코드에서 공통값을 관리하면서 초기화 방법을 조금 더 유연하게 가져갈 수 있다. |
| ScriptableObject | Inspector에서 편집하거나 Unity Object 참조가 필요 | 설정을 에셋으로 관리하고 여러 객체가 같은 데이터를 참조할 수 있다. |
| XML·JSON 설정 파일 | 구조화된 데이터가 많거나 표 형태의 수정이 필요 | 사람이 읽기 쉽지만 Deserialize, 검증, 스키마 관리가 필요하다. |
| 서버 설정 | 앱 업데이트 없이 운영 중 값을 변경해야 함 | 네트워크 실패에 대비한 캐시, 기본값, 설정 버전이 필요하다. |

- `Resources`는 데이터 종류가 아니라 설정 에셋을 앱 빌드에 포함하고 읽는 방법이다.
- XML, JSON, ScriptableObject 모두 Resources 아래에 둘 수 있다.
- `persistentDataPath`도 데이터 형식이 아니라 디바이스별 데이터를 읽고 쓰는 저장 위치다.

<br><br>

## :fire: 저장 방법을 고르는 질문
1. 이 값은 개발자가 바꾸는가, 사용자의 플레이로 바뀌는가?
2. 모든 사용자에게 같은 규칙으로 적용되어야 하는가?
3. 앱 업데이트 없이 값을 변경해야 하는가?
4. Inspector에서 편집하거나 Unity Object를 참조해야 하는가?
5. 값이 몇 개의 단순 상수인가, 많은 구조화 데이터인가?

```text
개발자만 변경
+ 모든 사용자가 같은 값 사용
+ 값이 적고 단순함
→ C# const

개발자·기획자가 Inspector에서 변경
+ Unity Object 참조 필요
→ ScriptableObject

구조화된 설정이 많음
+ 외부에서 읽고 수정할 필요가 있음
→ XML 또는 JSON

앱 업데이트 없이 운영 중 변경
→ 서버 설정
```

## :fire: HabitGame에서의 현재 선택
- `MoneyPerRoutineSuccess`, `MoneyPerSiestaMinute`는 사용자의 저장 상태가 아니라 게임의 보상 규칙이다.
- 현재는 개인 프로젝트이고 값이 두 개뿐이므로 `MyCharacterData.cs`의 `public const`로 관리한다.
- 루틴 기록, 낮잠 기록, 누적 재화는 사용자마다 달라지므로 Persistent XML에 저장한다.

```text
MyCharacterData.cs의 공통 설정
├─ MoneyPerRoutineSuccess
└─ MoneyPerSiestaMinute

Persistent MyCharacterData.xml의 사용자 상태
├─ RoutineRecordList
├─ SiestaTimeRecordList
├─ MonthlyRoutineSuccessMoney
├─ Name
└─ Age
```

- 프로젝트가 커져서 설정이 많아지거나 Inspector 편집이 필요해지면 ScriptableObject 또는 별도 설정 파일로 이동할 수 있다.
- 서버를 도입하면 서버 값을 우선 사용하고, 연결 실패 시 코드 기본값을 사용할 수 있다.
- 저장 방식을 바꾸더라도 사용자 상태와 게임 설정의 구분은 유지한다.

<br><br>

## :fireworks: 나의 판단 기준
> 사용자의 플레이로 달라지는 값은 사용자 저장 데이터로 관리한다. <br> 같은 설정 버전의 게임 전체가 동일하게 사용해야 하는 값은 게임 전역 설정 데이터로 한 곳에서 관리한다. <br> 값이 적고 개발자만 수정하는 개인 프로젝트에서는 C# `public const`를 우선 사용한다.
