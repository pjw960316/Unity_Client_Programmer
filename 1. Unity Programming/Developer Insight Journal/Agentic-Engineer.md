## :fireworks: 포폴 제작의 바이브
- 내가 포트폴리오 만든 과정
  - 초안 작성
    - 스스로 구조를 생각 및 초안 작성
    - 초안을 GPT와 검토
    - 초안 계속 수정 -> 3일 정도 걸린 듯 (매일 오랜 시간 투자했고)
  - 일단 작성
    - 초안에서 살을 붙인 문서 작성
    - markdown -> pdf는 프로그램으로
    - 지속적 수정
  - 최종 결과물을 AI에게 요청
    - AI는 내가 골조를 잡은 문서를 기반으로 결과물을 작성한다.
    - 골조가 있기 때문에 생성된다.
- AI의 결과물은 놀랍다. 그러나 나의 경험을 기반으로 프롬프트를 넣었고, 내가 계속 검토하고, 내가 일부는 적어보다 보니 결과가 나왔다고 믿는다.
- 개발도 같은 맥락이라고 생각한다. 이제는 전체 코드를 작성하는 건 인정하긴 싫지만 무의미한 것 같다. 그러면 결국 개발자는 뭘까? 양질의 초안 프롬프트(AI 친화적) 그리고 생산한 코드를 해석하는 능력.

## :fireworks: 앞으로 도입할 개발 방향
- 코드 작성보다는 AI-Assistant에게 설계의 초안을 넣는다.
  - 일반 문장
    - 유저가 참새를 터치하면 참새가 선택되고, 선택된 참새는 외곽선이 표시된다.
  - 개발자 문장 (물론 일반 문장을 이렇게 만들어 달라하면 못할 건 없다.)
  - 터치 입력은 InputController에서 감지하고, Raycast 결과는 InputManager가 FieldObject로 해석한다. 선택 상태는 FieldObjectManager가 단일 소유하며 선택 변경 시 해당 FieldObjectPresenter에게 View 갱신을 요청한다. FieldObjectView는 선택 여부를 판단하지 않고 외곽선 표시만 수행한다.
- 검토하고 공부한다.
