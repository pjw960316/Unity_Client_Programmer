## :fire: Codex에게 위임 할 것
#### :white_check_mark: Class를 새로 만들 때 초기 틀 구현.
- 시작이 매우 쉬워진다.

<br>

#### :white_check_mark: 귀찮은 단순 구현.
- UI 쪽 코드 작성과 프리팹을 싫어하는데 다 시킨다.
- 테스트 코드 작성 다 시킨다.

<br>

#### :white_check_mark: 예외 처리와 방어 코드 점검 및 구현.

- 예외 처리가 중요하다는 건 알고 있었지만, 테스트 코드처럼 직접 챙기기는 귀찮았다. 예전에는 방어 코드를 직접 작성했는데, 어떤 상황에서 어떤 처리를 해야 할지 기준이 뚜렷하지 않아 충분히 도움이 되지 않았다.
- 예외 처리 기준은 공부와 실제 개발 경험을 바탕으로 내가 쌓는다. 무엇을 검사할지, 실패하면 건너뛸지 중단할지, 어떤 조건에서는 적용하지 않을지를 정한다.
- 나는 기능 구현에 집중하고, Codex는 코드 리뷰에서 내가 정한 기준에 맞춰 빠진 방어 코드를 찾아 보완한다. 기준이 아직 없는 상황에서는 내가 판단할 지점을 설명하게 한다.

<br>

#### :white_check_mark: 개발 과정과 업무 기록 정리 초안 작성.
- 구현 내용, 문제 해결 과정, 주요 설계 결정을 Markdown 문서로 정리시킨다.
- AI가 작성한 기록을 직접 검토하며 내가 이해하고 경험한 내용을 남긴다.
- :star: 요즘 느끼는 건 결국, 정보가 아닌 내 경험이 기록에서는 더 중요하다. <br> 어차피 정보는 AI로 쉽게 얻으니까. <br> 하지만 내 경험은 세상에 유일무이하다.
  - 그러다보면 AI가 만들어 준 초안은 대부분 수정된다.
