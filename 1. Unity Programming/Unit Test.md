# 장점
- 테스트는 유연성, 유지보수성, 재사용성을 제공한다.
  - 잠정적인 버그를 해결하기에 좋기 때문에 버그에 대한 두려움이 줄 수 있다.
  - 이를 제대로 만들기 위해서는 가독성이 중요하다.

# 단점 (단점일 수 있지만 아닌...)
- 테스트 코드가 복잡할수록 실제 코드를 짜는 시간보다 테스트 케이스를 추가하는 시간이 더 걸리기 십상이다.
  - 하지만 작가는 그럼에도 불구하고 테스트 코드(=유닛 테스트)를 실제 코드 만큼 제대로 작성하는 것이 중요하다고 말한다. 테스트 코드를 대충 짜면 제대로 된 테스트도 하지 못하고 시간만 낭비한다고 한다.

# 잘 만드는 방법
- 가독성,가독성,가독성
- 빠르게 동작하도록 구현해야 한다.
  - 빠르지 않으면 테스트를 돌릴 엄두가 나지 않는다.
- 테스트들 끼리는 서로 의존하면 안 된다.
  - A 때문에 B에서 오류가 나면 누구 때문인지 알 수가 없다.
- 테스트의 결과는 bool로 나타낸다.
  - 성공 or 실패가 최고다.
