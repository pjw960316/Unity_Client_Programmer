# 코드 분석을 잘하는 팁
- **큰 흐름 파악은 당연히 해야 하는 것** 이다.
- **왜 이렇게 구조를 잡았을 지에 대해 궁금해 하는 것이 제일 중요하다.**
- 메서드 하나 하나를 딥하게 이해하는 것 보다는 동작방식을 간단히 이해하고 그 구조에서 왜 이런 구조를 잡았는지가 중요하다.
  - 메서드는 **그 메서드를 쓸 때 정확히 이해하는 것**은 중요하다. 하지만 클래스의 모든 메서드를 하나 하나 씩 딥하게 이해할 필요는 없다.
- 유니티에서 제공하는 메서드에 대한 궁금증이 있다면 해당 메서드를 구글에 검색해서 메서드의 동작 방식을 이해하자.
  - 해당 메서드 자체에 콜백 구조가 숨겨져 있는 경우도 있다.

# :star:가장 도움이 된 글
- [블로그 GOAT](https://dongwooklee96.github.io/post/2021/05/05/%EC%98%A4%ED%94%88-%EC%86%8C%EC%8A%A4-%EB%B6%84%EC%84%9D-%EB%B0%A9%EB%B2%95.html)
  - 오픈 소스를 분석하기 전에, 공식 문서를 통해서 사용법을 익히면 좋다.
  - 소스코드의 폴더 구성을 보면서, 대략적인 기능들과 아키텍처를 파악해볼 수 있다.
  - 처음에는 오픈 소스의 아키텍처를 파악한 후에, 디테일한 부분으로 이동하는 것이 좋다.
  - 각 모듈들이 어떤 역할을 하고 있는지 살펴보고 상호간에 어떻게 연결되어 있는지 파악하자.
  - 큰 아키텍처를 연필이나, 다이어 그램 도구로 직접 그려보면서 파악하는 것이 좋다.
  - :star:**클래스는 어떤 정보를 담고 있으며, 어디서 사용되는지, 그리고 어떤 방식으로 동작하는지 등을 파악하는 것이 좋다.**
  - :star:**모든 함수를 파악하려고 하지 말고, 조금씩 자신이 살펴보려는 기능과 관련된 함수 들을 파악하는 것이 좋다.**
  - 디버거를 통해서, BP (Break Point)를 걸어놓고 직접 실행해보면서, 코드의 흐름을 파악해보는 것도 많은 도움이 된다. 
    - 함수의 인풋(Input)에는 어떤 데이터가 들어오고, 아웃풋(Output)은 어떤 데이터를 반환하는지 파악하는 것이 좋다.
  - 자신에게 질문을 많이하는 것이 중요하다. 특정 기능에 대해서 “나라면 어떻게 개발했을까?” 라고 자신에게 질문을 던지고, 머리속에 어떻게 구현할 것인지를 먼저 생각을 해본다.
  - 코드를 무조건 많이 보는 것이 좋다. 코드를 인쇄하여 보는 사람들도 있다.
  - :star:**당장 관심있는(필요한) 부분부터 집중적으로 파악하라,** 방대한 시스템을 보다 보면은 금방 지루해지고, 갈 곳을 잃어버리는 수가 많은데, 당장 필요한 부분부터 집중해서 보는 것이 좋다.

# 혼자 연습할 때 코드 분석 하는 팁 : 적절히 스킵할 수 있는 능력
- Readonly 스크립트나 라이브러리 스크립트는 당장은 읽지 않아도 좋다.
  - 이런 스크립트는 어떻게 찾는가?
    - 해당 스크립트에 뭐라도 적으려고 할 때 막는 팝업 뜨는 스크립트.
    - 유니티나 다른 라이브러리이므로 내가 바꿀 수도 없고 코드의 의도도 질문 할 수 없다.
  - 물론 내가 해당 부분을 깊게 사용하는 개발을 해야 한다면?
    - 당연히 읽고 분석해야 한다.
