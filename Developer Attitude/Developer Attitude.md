# 회사
- 똑똑함, **절실함, 태도**가 중요하다. 똑똑함을 변화하는 건 어렵지만 절실함과 태도를 바꾸는 건 할 수 있다. 
  - 절실하면 올바른 태도가 나온다.
- **타인과 의견을 공유할 때 의도를 공유해야 한다.**
  - 공유할 문서를 작성하거나 타인에게 의견을 전달할 때 의도와 목적을 포함하지 않았다.
  - 공유할 문서는 내가 볼 문서가 아니다. 누군가 읽을 것을 염두하여 작성한다.
- 어려운 것 부터 공부하려 하지마라. 기본부터 충실히하고 다음 단계로 넘어가라. 순서가 중요하다.
  - 기초도 제대로 하지 못하는 사람은 반드시 실무단계에서 기초의 부족함으로 문제를 야기한다.
  - 그렇다고 어려운 걸 공부하지 말라는 건 아니다. 우선순위가 아니다.
- 모르는 건 모른다고 말해라. 
  - 상사는 예측가능한 아랫사람을 원한다. 
- 너무 삽질을 하고 있다면 최소한의 질문 프로세스를 만들고 사수에게 질문한다.
- 어떤 조직에 처음 들어간다면 시간이 많을 것 이다. 이때 해당 조직에서 정리한 문서들을 열심히 읽어본다.
  - 슬랙 메시지
  - 회의록
  - 기획서 (팀이 정해진다면)
- 업무 관리 툴로 Trello를 이용해보았다. 팀 전체가 무엇을 하고 있는지 카드만 보고도 파악할 수 있었다.
  - 메인 업무(적당한 기간동안 해야할 큰 업무들)와 오늘 할 업무를 체크리스트로 구현해서 관리하고 있다. 
  - 일을 리스트업 하기 때문에 업무를 관리하기 매우 용이하다.
- 회사의 가장 큰 장점은 협업을 할 수 있는 것 이다. 타인과 같이 개발을 잘 할 수 있는 사람이 되어야 한다.
  - 남의 코드를 읽고 해석하는 능력.
  - 회사의 코드 컨벤션을 유지하여 코드를 작성하는 능력.
  - 다른 파트(UI 디자이너, 기획자, QA, 아트)와 의견을 공유할 수 있는 능력.
- 회사에서 사용하고 있는 툴이 좋다면 적극적으로 학습해서 사용한다.
- 테스트 기능과 테스트 모드가 존재했다. 이 덕분에 개발을 하기 매우 용이했다.
- 누군가에게 질문하는 것도 중요하지만 회사의 코드가 사수라 생각하고 코드에서 답을 찾아라.
- 프로젝트 코드의 큰 흐름을 파악하는 것이 중요하다. 그 후에 중요한(보통 Framework) 모듈 스크립트는 뜯어서 이해해본다.
